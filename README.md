# Компонент отрисовки теста

Проект: Qt 6, C++17, QOpenGLWidget, OpenGL 3.3 Core. Открыть dough.pro в Qt Creator,
выбрать комплект Qt MinGW и собрать. main.cpp запрашивает профиль OpenGL до QApplication.

## Главный контракт

Симуляция -> извлечение поверхности -> DoughFrame -> myOpenGLWidget::setFrame.

Компонент принимает готовую поверхность, а не рецепт, частицы, температуру или объёмную
сетку. Физику, преобразование физических величин в визуальные параметры и построение
поверхности реализует вызывающий код. Это позволяет использовать FEM, частицы,
воксели или другую внутреннюю модель независимо от OpenGL.

В doughframe.h находятся два массива:
- vertices: вершины поверхности с материалом;
- indices: индексы вершин, каждая последовательная тройка образует треугольник.
  Например, {0,1,2, 0,2,3} задаёт два треугольника из четырёх вершин.
  Индексы начинаются с нуля.

DoughVertex содержит:
| Поле | Что передавать |
| --- | --- |
| x,y,z | Положение в метрах; правая система координат, Y вверх |
| nx,ny,nz | Нормаль от материала к воздуху; ненулевая, желательно единичная |
| cooked | 0 — сырой вид, 1 — готовый мякиш; влияет на базовый цвет |
| browned | 0 — без корочки, около 0.5 — коричневая, 1 — обугленная |
| moisture | 0 — сухая матовая, 1 — влажная блестящая поверхность |

Все три параметра материала — float в [0,1]. Это художественные коэффициенты,
а не измеренные температура, концентрация воды или степень химической реакции.
Их связь с реальностью необходимо отдельно калибровать на экспериментах.
Готовность и подгорание независимы: обгорелая снаружи заготовка может быть сырой внутри.

Обход треугольников: против часовой стрелки при взгляде со стороны воздуха.
На стенках пор нормали смотрят внутрь полости. Для резкой границы материала или
нормалей дублируйте вершины. Между вершинами материал интерполируется;
для маленького подгорелого пятна нужны достаточно мелкие треугольники.

## Вызов

Минимальный пример поверхности одного треугольника:

```cpp
DoughFrame frame;
frame.vertices = {
    {0,    0, 0,     0,0,1,    0.8f,0.4f,0.2f},
    {0.10f,0, 0,     0,0,1,    0.8f,0.4f,0.2f},
    {0,0.10f, 0,     0,0,1,    0.8f,0.4f,0.2f}
};
frame.indices = {0,1,2};

QString error;
if (!widget->setFrame(std::move(frame), &error))
    qWarning() << error;
widget->resetCamera(); // Один раз при загрузке новой сцены.
```

setFrame вызывается в потоке GUI. Данные передаются по значению: std::move передаёт
владение без копирования массивов. После успешного вызова виджет хранит свой снимок.
Ссылки на рабочие данные физики не сохраняются. Пустой DoughFrame очищает сцену.
Ошибочные индексы, NaN/Inf, нулевые нормали, параметры вне диапазона отклоняются:
метод возвращает false, предыдущий кадр остаётся. Геометрическая корректность
(самопересечения, замкнутость, вырожденные треугольники) остаётся обязанностью отправителя.

Физика из рабочего потока может отправить снимок через очередь Qt:

```cpp
// worker: готовый снимок, widget должен жить до окончания отправки.
QMetaObject::invokeMethod(widget,
    [widget, frame = std::move(frame)]() mutable {
        QString error;
        if (!widget->setFrame(std::move(frame), &error))
            qWarning() << error;
    }, Qt::QueuedConnection);
```

Остановите отправителя до уничтожения виджета. Для быстрой симуляции ограничивайте
частоту публикации кадров или используйте один заменяемый последний снимок:
очередь всех промежуточных состояний иначе будет накапливаться. Шаг физики и
частота отображения не обязаны совпадать. update() планирует перерисовку средствами Qt.

## Рост, поры, разрезы

Пышность приходит через изменение координат и геометрии. Отдельного коэффициента
пышности в контракте нет. Если появляются поры, разрывы или сливаются поверхности,
можно менять количество вершин и индексов при каждом вызове setFrame.

Для настоящей пористой структуры нужны поверхности стенок полостей. Внешняя
непрозрачная оболочка скрывает внутренние поры, как в реальности.
Для просмотра мякиша включите «Срез по X» и перемещайте ползунок (миллиметры).
В коде: widget->setSlice(true, xInMetres); отключение: setSlice(false, 0).
Остаётся часть x <= координата среза. Компонент строит пересечения треугольников
с плоскостью и заполняет сечение по правилу чётности через stencil buffer.
Вложенные замкнутые оболочки полостей оставляют отверстия в сечении.
Требуется stencil buffer 8 бит (запрошен в main.cpp).
Сетка должна быть замкнутой, без самопересечений и перекрывающихся тел:
для открытых поверхностей заполнение не определено. Совпадение плоскости с
гранями может давать пограничные артефакты; немного сместите срез.
Срез рисуется единой плоскостью через stencil-маску, без перекрывающихся
цветных треугольников. На нём процедурно рисуется мякиш с порами разной формы.
setFluffiness(value) задаёт количество пор: 0 — без пор, 1 — максимальное.
Поры — рисунок с имитацией глубины, не геометрические полости. Рисунок стабилен
в координатах YZ и не зависит от времени; при смещении среза по X он повторяется.
Объёмные поля состояния не передаются, цвет среза художественный.
Срез пересчитывается на CPU при каждой перерисовке с включённым сечением;
производительность на больших сетках пока не измерена.

Для MPM потребуется адаптер из материальных точек в замкнутую поверхность
с сохранением пустот. Тип вещества и объём точки понадобятся этому адаптеру;
текущий виджет продолжает принимать DoughFrame. Газ можно визуализировать
как пустоту, если его граница уже восстановлена. Это не определяет, как
рассчитывать газ в вашей физической модели.

Если ваша модель объёмная, отделите от физики адаптер построения поверхности.
Например, для поля материала можно извлекать изоповерхность, а визуальные
поля интерполировать в полученных вершинах. Этот адаптер здесь не реализован.

## Как работает отрисовка

setFrame проверяет и сохраняет CPU-снимок, затем вызывает update().
В initializeGL создаются шейдеры, VAO, буфер вершин VBO и буфер индексов EBO.
В paintGL изменённые массивы целиком загружаются на GPU; неизменный кадр повторно
не загружается. Вершинный шейдер применяет матрицы камеры, фрагментный рассчитывает
цвет и освещение. Есть глубина, направленный источник света, фоновое освещение,
блик в зависимости от влажности и приближённая гамма-коррекция.
Это простой художественный материал: без рассеяния света внутри мякиша,
теней между поверхностями, текстур и физически откалиброванной оптики.
Внутренние поры могут выглядеть светлее ожидаемого из-за отсутствия затенения полостей.

Ресурсы освобождаются при уничтожении контекста; сохранённый CPU-снимок позволяет
повторную загрузку при пересоздании контекста. Ошибка шейдера показывается в виджете
и доступна через rendererError(). При полной невозможности создать контекст
диагностику создания QOpenGLWidget выдаёт Qt.

Камера вращается ЛКМ, колесо меняет расстояние, «Вписать» центрирует текущую геометрию.
При следующих кадрах камера сохраняется, поэтому рост не маскируется автоматическим
масштабированием. Рекомендуются объекты умеренного размера около начала координат.

## Демонстрация и проверка

demodough.cpp генерирует кольцевую заготовку с настоящим сквозным отверстием.
Ползунки mainwindow.cpp меняют геометрию и материал. «Пышность» управляет
числом нарисованных пор и толщиной заготовки. «Движение» включает/приостанавливает
простую демо-анимацию: синусоидальные растяжение, сдвиг и перемещение.
Масштабы по трём осям имеют произведение 1, нормали преобразуются соответственно.
Таймер обновляет форму примерно 30 раз в секунду. Это наглядная деформация,
без расчёта сил, столкновений или MPM; при задержках интерфейса демо замедляется.
Удалена демонстрационная внутренняя геометрическая полость.
При подключении своей модели замените генератор вызовами setFrame; сам виджет
не зависит от демонстрации.

Проверка tests/renderer_smoke.pro: неправильные данные, ориентация треугольников
демонстрации, создание контекста, компиляция шейдеров, наличие геометрии в кадре,
смена материала, очистка и повторная загрузка. Тест запускается с графическим
контекстом и сохраняет preview.png и preview-charred.png в рабочую папку.
На установленном Qt 6.11.0 / MinGW сборка и этот тест пройдены.
